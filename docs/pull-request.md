# Install from GitHub with isolated per-user data and a production launcher

The previous launcher required a live Vite development server and stored SQLite, workspace and Google authentication beside the backend source. Install/update now builds a separate per-user release, installs `chanthecno-hub` in `~/.local/bin`, and serves the production frontend and API through one loopback server. No sudo or npm package publication is used. Reinstallation and uninstall preserve user data/configuration by default; PATH, GitHub update/uninstall, and individual-account OAuth instructions are documented.

Shared paths and atomic storage isolate data from code and credentials. Offline reset/restore requires explicit confirmation, refuses active/uncertain work, verifies a SQLite/WAL-aware backup first, and leaves OAuth configuration and Google resources untouched. Colab/Drive connection handling and GPU checks reuse the existing guarded connection lifecycle. Model history remains selectable after a newer failed job or failed backup, existing runtime artifacts avoid a repeated restore, stale progress requires a fresh worker heartbeat, and retrying backup never starts training.

Model Testing uses the chosen model name, a collapsible mobile library and a visible composer. Retrieval indexes filtered documentary sentences, keeps source/Drive IDs and quote offsets, and refuses unfiltered legacy indexes; the same adapter/model can answer from general knowledge when project evidence is missing, with cautious attribution. This is not evidence of improved real-model quality. Checkpoint resume now requires optimizer/scheduler/RNG state with matching checksums. Legacy checkpoints without these integrity markers are rejected for exact resume.

Validation: 113 offline backend tests on each of Python 3.10.12 and 3.12.14, real temporary-directory install/reinstall/start/shutdown/uninstall smoke, production build, lint (18 warnings, exit 0), and Chromium desktop/mobile plus dataset-selection/status tests with mocked APIs. Screenshot fixtures and detailed evidence are in `docs/validation.md`. Google OAuth/Drive/Colab/T4, full training/resume, Linux Mint memory use, and adapter quality were not tested against real services. CI configuration is included but its remote run is unverified. No credentials were read or distributed; no Google resources were changed. See README for retained limitations, reset scope and recovery commands.

Python 3.10.12 is now supported after real dependency installation, pip consistency checks, tests and production install smoke; backend pins are unchanged. The Google SDK end-of-support warning remains documented. The installer keeps Python system interpreters untouched. CI covers both Python versions.

Dataset selection is explicit. The backend verifies selected local bytes and live Drive ID, project datasets folder, size and API content checksums before creating a preparation thread, then checks again before opening a runtime and hashes downloaded bundle data. Per-run manifests are immutable and included in worker/run metadata. Drive uploads reserve and journal an ID before sending bytes; retry after lost acknowledgment reuses it. Adding datasets does not authorize checkpoint resume.

CTH 1.1.0 adds a sidebar version and explicit public GitHub stable-release checks with bounded time/response size, persistent throttling, rate-limit handling and honest unknown/no-release states. Release notes are plain text and update instructions use a fresh tagged clone. No Google credentials or project data are sent. First installs are not announced as upgrades; a new installed version must serve the UI before a notice appears, and seen versions persist in user data. The installer probes a new release with isolated data before atomic activation, rejects active/uncertain work, and rolls back on command-link failure. Mock release checks and desktop/mobile browser evidence cover the lifecycle; no actual GitHub Release was published.

CTH 1.1.1 reports dataset format, detected QA pairs, pre-tokenizer training units, searchable quotes and skipped lines separately. TXT conversations are not silently converted or trusted. Explicit file purposes separate training-only conversations from facts-only retrieval sources; original bytes/checksums stay unchanged. Empty indexes require a clear pre-training warning and server-side acknowledgment, and restored models with empty/unknown source counts are never presented as source-ready. Saved models can receive a verified facts-only inference index through an explicit refresh without retraining or rewriting the original run manifest. Tests cover identical identity facts in plain/QA formats, mixed/untrusted answers, source policies, immutable input, empty warnings, cache integrity and model reindex. No real training was run.

CTH 1.1.2 additionally allows USER/ASSISTANT answers as retrieval sources only after explicit per-file curated_qa approval. It extracts bounded answer sentences, uses the question only as search metadata for single-sentence answers, rejects embedded instructions/orphan turns, and preserves default conversation exclusion. Curated QA can refresh a saved model index without retraining; Drive verification, immutable run manifests and original dataset bytes remain protected. Offline fixtures cover approved/unapproved identical identity facts, unrelated QA, mixed turns, multiline/oversized pairs, injection attempts, explicit refresh and Drive failure.
